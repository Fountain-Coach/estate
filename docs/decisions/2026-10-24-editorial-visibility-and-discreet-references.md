# Publication visibility, private provenance and return paths

**Author decision (24 October 2026).** Works is an off-reel author-side source and preparation context; Book is the public reader-facing explanation/publication of admitted works. Status is a separately owned, public but off-reel company/transparency source. Status needs a bounded place for intentionally less-prominent, recipient-directed documentary references, without publishing personal files or implying that off-reel means private.

## Three independent questions

1. **Ownership:** Which Git source controls a work, record, reference or release?
2. **Visibility:** Is it featured, discreetly public, or genuinely private?
3. **Publication state:** Is this a source candidate, WLAN staging artifact, or separately authorized public HTTPS release?

Neither off-reel placement nor search-engine opt-out protects a publicly served URL. A private source must never be materialized into public static source or a public static release simply to give a recipient a link.

## Preferred roles and links

- **Book (featured):** editorial entrance to authorized, actually readable editions; links to their source-owned reading routes and can return from those routes. Reframe Bookshelf admission remains separate from public publication.
- **Works (public supporting/off-reel):** source custody, original credits, professional context, original documents and candidate edition preparation. An individual public work can be linked from Book; its page should carry intelligible publisher/source relationships. Works is *not* the actual private WLAN staging server.
- **Status (public supporting/footer-only):** company condition, evidence and transparency; `/references/` identifies the protocol for recipient-directed references. The route is available via the Status `/transparency/` section and carries ordinary explicit return links. No new reel item, public archive of personal cases or tracking application.
- **Genuinely private records:** original benefit-agency/Jobcenter files, named correspondence, account/payment records, identifiable case evidence and unpublished legal papers stay in access-controlled storage and move to recipients only by agreed controlled delivery. Even a redacted public statement needs review before a public URL is issued.

## Backlink contract

Every promoted public book or discreet public reference has a clear context link and return route, title, author/publisher, edition or document date/revision, and an explicit distinction from private source. Primary editorial discovery is a different link obligation from provenance and return navigation. For discreet references, ordinary, non-JavaScript links suffice; no popup or custom copy action. Private files are not forced to expose backlinks in public navigation.

An unlisted URL does not guarantee anonymity: the server or transport can record request metadata. The Status reference page includes no tracking scripts, cookies, external fonts/media or analytics, but the network/host layer must be independently verified before promises about logging. Noindex and no-referrer tags are only browser/crawler signals.

## Enforcement owner and rollout

Publication identity/reel: Fountain-Coach/estate `navigation/canonical-reel.v1.json` and approved shell. Status source/public reference protocol: Fountain-Coach/status.fountain.coach (`site/references/index.html`). Works owns its authored work and original data; Book owns its public publishing explanation. Specific redaction or rights clearance is not assumed. Any actual recipient document requires a separate explicit selection, redaction review, intended use authorization and publication/delivery decision.

Git development -> existing owner-WLAN Ubuntu staging -> separately authorized public production, no new DNS stage or public private-record storage. Initial staged reference section contains **no personal correspondence**; public production of Status and any personally sensitive file is unchanged.
